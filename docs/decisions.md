# Argus 关键决策记录

> 记录项目推进过程中的重要技术决策及其理由

## ADR-001: 编程语言选择 Rust

- 日期: 2026-09-19
- 状态: 已决定
- 决策: 完全基于 Rust 实现所有核心引擎和编排层
- 理由:
  - 单二进制部署（无需安装运行时）
  - 内存安全（无缓冲区溢出，安全工具本身不能有安全漏洞）
  - 极致性能（扫描并发能力强，口令爆破场景优势明显）
  - 交叉编译（适配多架构部署 X86/ARM）
- 例外: 前端使用 Vue3（Rust 前端生态不足以支撑复杂管理后台）

## ADR-002: Web 框架选择 actix-web

- 日期: 2026-09-19
- 状态: 已决定
- 决策: 使用 actix-web 而非 axum
- 理由:
  - Actor 模型天然适合扫描任务调度（每个引擎一个 Actor）
  - 更成熟的生态和中间件
  - 性能基准优异
  - 社区活跃度高

## ADR-003: ORM 选择 sea-orm

- 日期: 2026-09-19
- 状态: 已决定
- 决策: 使用 sea-orm 而非 sqlx/diesel
- 理由:
  - 复杂领域模型（资产→漏洞→任务→报告）需要 ORM 抽象
  - 异步原生支持（基于 sqlx）
  - 宏自动化实体生成
  - with-chrono/with-json features 满足需求

## ADR-004: 插件引擎三层混合架构

- 日期: 2026-09-19
- 状态: 已决定
- 决策: YAML 模板 + Rhai 脚本 + WASM 插件三层混合
- 理由:
  - 80% 检测规则是简单的 HTTP 请求+响应匹配，YAML 模板最高效
  - 15% 需要条件逻辑，Rhai 提供语言级沙箱
  - 5% 复杂协议交互，WASM 插件提供最强隔离和性能
  - 三层覆盖不同复杂度的检测场景，安全研究员按场景选择
- 关键: 插件做成独立引擎 crate (argus-engine)，9 大扫描引擎共享

## ADR-005: 漏洞知识库策略

- 日期: 2026-09-19
- 状态: 已决定
- 决策: 混合策略（NVD 数据 + 自研 Top500 + 渐进积累）
- 理由:
  - 全量自研 47 万条规则需 10+ 人年，不现实
  - NVD/CVE 是公共数据，导入不算依赖外部引擎
  - 先覆盖 Top 500 高频漏洞达到 80% 实用率
  - 后续按客户需求逐条补充
- 目标: 阶段 4 完成时达到 30-40% 覆盖率，可商用试用

## ADR-006: 前端技术选型

- 日期: 2026-09-19
- 状态: 已决定
- 决策: Vue3 + Element Plus
- 理由:
  - 此类产品普遍有大量复杂前端交互（配置页、趋势图、大屏、报表）
  - Rust 前端（yew/iced）无法支撑复杂管理后台
  - Vue3 生态成熟，Element Plus 有完整组件库
  - 前后端分离不影响 Rust 核心能力

## ADR-007: 浏览器引擎调用策略

- 日期: 2026-09-19
- 状态: 已决定
- 决策: 通过 chromiumoxide 驱动 Chrome CDP
- 理由:
  - Web 爬虫需要 JS 渲染，纯 Rust 无替代方案
  - 浏览器自动化大概率也是调用 Chrome（CDP）实现
  - chromiumoxide 提供 Rust 绑定
  - 这不算"依赖外部引擎"，只是调用浏览器

## ADR-008: 项目定位与推进策略

- 日期: 2026-09-19
- 状态: 已决定
- 决策: 以商业级安全扫描产品为对标，分阶段实现
- 推进顺序: 地基→端口扫描→口令猜解→基线核查→系统扫描+知识库→应用扫描→数据库/镜像/工控→移动/漏洞验证→报表/大屏/系统管理
- 第一个商用里程碑: 阶段 4 完成后（40% 覆盖），可小范围试用

## ADR-009: 项目命名

- 日期: 2026-09-19
- 状态: 已决定
- 决策: Argus（阿尔戈斯）
- 理由: 希腊神话中拥有 100 只眼睛的巨人 Argus Panoptes，化身全知全见的守卫者，与安全扫描系统"全面发现、不遗漏"的核心价值完美对应

## ADR-010: 知识库作为数据而非代码

- 日期: 2026-09-19
- 状态: 已决定
- 决策: NVD/CVE 数据库导入是数据层面操作，不违反"完全 Rust"原则
- 理由: NVD 是公共 JSON/XML 数据，导入到 PostgreSQL 不涉及外部代码运行时
